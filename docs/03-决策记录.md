## D-001 主战场是 Web 还是小程序

**背景**：家长与老师的打印动作大多发生在电脑端；但国内用户触达和分享习惯在微信。

**选项**
1. Web 优先，小程序只做浏览、收藏、分享，打印引导到 Web。
2. 小程序优先，导出 PDF 后转发到电脑打印。
3. 两端同步开发。

**建议**：选项 1。设计器、预览、精确打印在电脑端体验最好，小程序做轻量入口即可。

**状态**：待定。

## D-002 画布引擎

**背景**：田字格、米字格、回宫格、竖排界栏、注音对齐、描红轮廓都是很特殊的排版规则，通用设计编辑器不直接支持。

**选项**
1. SVG 自研：每页就是一棵 SVG 树，元素坐标全部用毫米换算，PDF 导出天然矢量。
2. Konva / Fabric.js：拿到拖拽、变换、图层等交互能力，但导出矢量 PDF 需要额外工作，文字排版要自己做。
3. Polotno SDK：Canva 式编辑器开箱即用，但为商业授权，且对竖排与网格没有原生支持。

**建议**：选项 1。交互层可以自己实现拖拽与吸附，工作量可控；矢量输出与打印精度是产品命脉，不能被引擎限制。可以参考 Polotno 的 JSON 文档结构来设计模板 schema。

**状态**：待定。

## D-003 内容库来源

**背景**：开源数据（chinese-poetry 等）体量大但错字、异文、无拼音；蒙学经典有多个版本。

**选项**
1. 先人工校对一份核心库（蒙学七八种加小学必背古诗），再逐步扩充。
2. 直接导入开源数据集，靠用户纠错。

**建议**：选项 1。印在纸上给孩子练的内容，错一个字影响极大。核心库宁少勿错，扩充库可以引入开源数据并标明「未校对」。

**状态**：待定。

## D-004 PDF 生成位置

**建议**：MVP 用客户端 pdf-lib 加 SVG 转换，零服务器成本；V1 加服务端 Chromium 渲染通道，用于整本练习册和高保真需求。

**状态**：待定。

## D-005 字体策略

**建议**：MVP 只内置可商用开源字体（霞鹜文楷、思源宋体、思源黑体等），用户可上传自有字体但需自行确认授权。隶书、篆书等书法字体缺少高质量开源版本，作为 V2 采购项评估。

**状态**：待定。

## D-006 简繁策略

**建议**：简体优先。数据层从第一天起就保留繁体字段，避免以后返工；界面与内容的繁体版本放到 V2。

**状态**：待定。

## D-007 游客导出

**建议**：允许不登录导出，页面带小水印和校准尺。降低首次体验门槛，同时给登录和付费留出理由。

**状态**：待定。

## D-008 注音策略

**背景**：注音是数据、排版、流程三方面成本最高的功能，也是最容易出错、最容易被投诉的地方；但学前与一年级的家长几乎都需要它。

**选项**
1. 注音必选，所有纸张默认带拼音。
2. 注音可选，默认值由模板与内容共同决定。
3. 注音全部后置到 V1。

**结论**：选项 2。识字表、学前与一年级内容默认开；临摹、竖排、卡片、二年级以上默认关。关闭注音的路径最短：自定义文本不注音时直接出纸，注音核对只在开启注音时出现。内置内容仍保存拼音数据，核心库人工校对，扩充库标「未校对」。「只标多音字」「按年级只标未学过的字」作为 P1。

**状态**：已定，2026-09-25。

## D-009 篇目组合的命名

**背景**：用户从库里挑出若干篇目、按顺序编在一起、装订成册打印，这个对象需要一个名字。「合集」太泛，「练习册」把输出物和组合混在一起，也限定了用途。

**候选**
1. 文选：编选的篇目，常用词，与蒙学气质一致，不与作业、课本混淆。输出动作叫「装订成册」。
2. 课本：直观，但容易被理解为部编版教材。
3. 功课：蒙学味浓，隐含每日任务，可能与作业混淆。
4. 篇单：仿歌单、书单，好懂但不是现成词。

**当前**：原型与 PRD 使用「文选」。

**状态**：待定，等产品负责人拍板。
